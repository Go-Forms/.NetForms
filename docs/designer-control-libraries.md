# Дизайнер: библиотеки контролов (проект)

Статус: **предложение, не реализовано** (решение 157 в `docs/PLAN.md`). Документ фиксирует обсуждение с заказчиком
2026-09-25: как дать дизайнеру контролы из сторонних библиотек и из своего кода.

## Что есть сейчас

- Свойства и события дизайнер берёт рефлексией и атрибутами `System.ComponentModel`, превью рисует сам NetForms.
- Но набор сборок фиксирован: `TypeResolver.DefaultAssemblies()` — NetForms, `System.Drawing`, BCL. Список тулбокса
  зашит в `DesignerToolbox.cs`.
- Тип, которого нет в этих сборках (свой контрол проекта, контрол из NuGet), на холсте становится
  `DesignerPlaceholder` — пунктирная рамка с именем типа; его свойства пишутся дословно, но не редактируются.
- Точка расширения уже есть: `DesignerCodeReader(IEnumerable<Assembly>)` и `DesignerCodeWriter(IEnumerable<Assembly>)`.

## Идея: команды, а не неявное подключение

Библиотеку подключает пользователь явной командой — ничего не ставится «само» при перетаскивании или открытии формы.

Команды палитры VS Code:

- **NetForms: Add Control Library…** — быстрый выбор источника:
  1. NuGet-пакет по имени;
  2. `.dll`-файл;
  3. `.nupkg` или локальная папка-фид;
  4. папка этого проекта со своими контролами;
  5. другой `.csproj`;
  6. NuGet, уже прописанный в csproj этого проекта.
- **NetForms: Remove Control Library** — убрать группу из тулбокса (и, по желанию, ссылку из csproj).
- **NetForms: Rescan Toolbox** — пересканировать после сборки.

## Один конвейер для всех источников

Команды отличаются только тем, **как библиотека попадает в проект**. Дальше путь общий:

```
источник → [правка csproj, если нужна] → dotnet build →
сборки проекта (bin + deps.json) → скан → «найдено N контролов» (галочки) → группа в тулбоксе
```

Свой резолвер NuGet/зависимостей/версий не пишем — это делает MSBuild. После сборки хост дизайнера берёт выход
проекта и грузит его в **collectible `AssemblyLoadContext`** (зависимости — через `AssemblyDependencyResolver` по
`deps.json`). Транзитивные пакеты, нативные ассеты и конфликты версий решаются ровно так же, как при запуске
приложения. Сборки передаются в `DesignerCodeReader`/`DesignerCodeWriter` вместе с `DefaultAssemblies()`.

| Источник | Что меняется в csproj | Особенности |
|---|---|---|
| 1. NuGet по имени | `dotnet add package X --version Y` | Автодополнение по nuget.org, выбор версии; до добавления пакет скачивается во временную папку и проверяется (см. ниже) |
| 2. `.dll` | `<Reference Include="…"><HintPath>…</HintPath></Reference>` | Предложить скопировать файл в `libs/` проекта — иначе на другой машине проект не соберётся |
| 3. `.nupkg` / фид | папка — источник в `nuget.config`, дальше как 1 | Корпоративные и собственные пакеты |
| 4. Папка в проекте | ничего | Контролы компилируются вместе с проектом; команда лишь заводит для папки (пространства имён) отдельную группу тулбокса |
| 5. Другой `.csproj` | `dotnet add reference` | Пересканирование после каждой сборки того проекта (слежение за его выходной `.dll`) |
| 6. NuGet из csproj | ничего | Пакеты — из `obj/project.assets.json`; пользователь отмечает, какие показывать |

### Контролы своего проекта

Как в Visual Studio (группа «компоненты проекта»), контролы текущего проекта подхватываются **автоматически**;
команда 4 нужна только чтобы вынести папку в свою группу. Тонкость: форма и её контролы — одна сборка. Дизайнер
работает с последней **успешной** сборкой; если сборка сломана — с закэшированной теневой копией, а новые типы
остаются заглушками до следующей удачной сборки.

## Проверка перед добавлением

Скан — через `System.Reflection.MetadataLoadContext`, **без выполнения** кода библиотеки:

- ✅ собрана под NetForms (ссылается на сборки NetForms) — подключаем;
- ⚠️ собрана под настоящий `System.Windows.Forms` — предупреждение про CS0012 и strong name (решение 136, ждёт
  заказчика): добавить можно, но на Linux, скорее всего, не соберётся;
- ⚠️ нативные ассеты только в `runtimes/win-*/native` — работает только на Windows;
- ❌ нет подходящего TFM (`net10.0` или совместимого) — не добавляем и объясняем почему.

Затем превью: найденные контролы и компоненты — публичные, не абстрактные, с конструктором без параметров, без
`[ToolboxItem(false)]` и `[DesignTimeVisible(false)]`, с иконкой из `[ToolboxBitmap]` (или иконкой по умолчанию).
Пользователь снимает лишние галочки.

## Где что хранится

| Что | Где | Почему |
|---|---|---|
| Ссылки на библиотеки | csproj | Единственный источник правды для сборки |
| Состав тулбокса: какие контролы, группы, порядок | `.vscode/netforms.json` в проекте | Коммитится — у коллег тулбокс тот же |
| «Недавние библиотеки» | `globalStorage` расширения | В новом проекте они первые в списке команды: один выбор — и библиотека поставлена, и в тулбоксе |

Если ссылка из csproj пропала — группа тулбокса скрывается (а не ломает дизайнер); `Rescan` её убирает.

## Риски

- **Чужой код исполняется.** Конструкторы и `OnPaint` сторонних контролов выполняются в хосте дизайнера. Нужны
  Workspace Trust (в недоверенной папке — только скан метаданных, без загрузки) и подтверждение для пакетов не с
  nuget.org. Исключение в `OnPaint`/конструкторе — плашка с красным крестом и текстом ошибки вместо контрола, а не
  падение. Хост — отдельный процесс, VS Code его падение не роняет; хост перезапускается.
- **Блокировка файлов на Windows.** Сборки грузятся из теневой копии, иначе `dotnet build` упрётся в занятую `.dll`.
- **Выгрузка.** Collectible ALC — чтобы после пересборки перезагрузить контролы без перезапуска хоста; ссылки на
  типы из выгружаемого контекста не должны утекать в кэши `TypeDescriptor` (сбрасывать `TypeDescriptor.Refresh`).
- **Дизайн-тайм-атрибуты сторонних библиотек** (`[Designer]`, свои `UITypeEditor`, `TypeConverter`) — сначала
  используются только конвертеры; свои дизайнеры и редакторы — позже, отдельным решением.

## Порядок реализации

1. **Контролы своего проекта (автоматически) и NuGet, уже прописанный в csproj (п. 6).** csproj не меняется, а это
   большинство реальных случаев. Сюда же — загрузка в collectible ALC, группы тулбокса, `.vscode/netforms.json`,
   плашка ошибки вместо упавшего контрола.
2. **Другой `.csproj`** (п. 5).
3. **`.dll`** (п. 2).
4. **NuGet по имени и `.nupkg`/фид** (п. 1 и 3): поиск, выбор версии, проверка до установки.

Каждый этап — тесты хоста (фикстура: маленькая библиотека контролов в `tests/`, собранная под NetForms) и UI-тест
расширения на команду.
